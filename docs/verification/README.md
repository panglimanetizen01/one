# Verification artifacts and evidence boundary

The canonical private repository may contain concise, durable verification contracts, status records, templates, and links to exact-SHA evidence when they are required to explain or reproduce the project's acceptance state.

Full workflow definitions dedicated to the independent verification lab, temporary run output, bulky logs, and generated evidence bundles should remain in the external verification repository unless explicitly approved for canonical inclusion. Link to those records rather than copying volatile output into this repository.

GitHub `main` remains the sole source of truth for One source code, specifications, contracts, and accepted project documentation. An external verifier is execution/evidence infrastructure only; it does not replace or redefine canonical source state.

Every verification claim must identify the exact source SHA, workflow/run, platform boundary, and result. A documentation or evidence-index update does not itself prove a source capability or award acceptance points.
