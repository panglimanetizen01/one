# One v0.1 Completion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the remaining implementation gaps required by the approved One v0.1 contracts without purchasing GitHub capacity, while keeping GitHub `main` canonical and preserving independent offline verification as the fallback evidence path.

**Architecture:** Keep the existing pipeline `source -> lexer/parser -> AST -> semantic analysis -> CSIR -> reference interpreter`. Complete the v0.1 execution boundary around that pipeline rather than replacing the language core. Build/package artifacts remain explicitly non-native in v0.1; native compilation, full FFI, package registry, IDE, and additional locale grammars remain future scope unless the existing release contract already marks them in-scope.

**Tech Stack:** Rust 2024 workspace, Cargo, existing `one-core` and `one-cli`, deterministic local fixtures, Bash/PowerShell offline verification.

**Spec:** `docs/release/one-v0.1.md`, `docs/spec/one-v0.1-cli-contract.md`, `docs/spec/one-v0.1-package-build.md`, `docs/spec/one-v0.1-standard-library.md`, `docs/spec/one-v0.1-platform-abstraction.md`, `docs/spec/one-v0.1-effect-capability.md`, `docs/spec/one-v0.1-conformance-suite.md`.

## Global Constraints

- GitHub `main` is canonical; work lands through the implementation branch and normal repository review/merge flow.
- Do not purchase or enable a paid GitHub upgrade to obtain hosted runner capacity.
- Hosted GitHub CI must remain explicitly blocked unless it independently becomes usable; it must never be represented as green without execution evidence.
- Offline verification is portable evidence and must record exact commit/toolchain/environment.
- No LLM or network service may become semantic authority or a runtime/build dependency for offline operations.
- Ambiguous source is rejected deterministically; no guessing or hidden repair.
- Capability checks occur before host effects and default to deny.
- Existing stable diagnostic families/codes remain compatible unless a contract explicitly requires a new code.
- No unrelated UI, product, or speculative features.

## Review Focus

- A malformed or ambiguous source must stop at the earliest valid stage and return a stable diagnostic.
- A denied process/effect must not reach the host adapter.
- A package/build artifact must be byte-stable for identical declared inputs.
- CLI output and exit status must remain deterministic and exact for primary Indonesian commands and aliases.
- Platform-specific behavior must not silently substitute an unsupported operation or target.

## CI provider update — 2026-11-13

The earlier hosted-CI blocker and GitHub Actions wording above describe the historical provider. CircleCI is now the selected canonical CI execution provider under ADR-0017. The CircleCI migration is tracked in `docs/CI.md`; the old GitHub Actions workflows remain temporarily until CircleCI exact-SHA parity is proven. Independent Linux/Windows verification remains a separate evidence channel.
